# 买或租：原始需求与新手体验自审

审核日期：2026-10-22。依据本对话原始需求、当前源码、实际浏览器操作、最新测试和政策原文。结论：核心功能可用于演示；并非所有早期体验设想均已完成，也未经过真实新手的可用性测试。

## 需求对照

| 需求 | 实际情况 | 结论 |
|---|---|---|
| 从简单开始，逐渐加参数 | 默认仅房价、住房月租两个输入；收益率、比较期可展开，房贷/公积金/费用按需加入 | 符合；尚缺“公式逐步演化”的直接展示 |
| 闲钱收益率默认1.5% | 1.5%，可修改，提示为假设 | 符合 |
| 自住与买后出租 | 两用途分开，住房开销与出租净收入独立；出租可拆空置和费用 | 符合；共同居住成本抵消以两边相同为前提 |
| 租售比 | 展示年度净租金/总价；自住查看收益率不会额外收到租金 | 符合净收益率口径，不是传统挂牌月租/售价口径 |
| 商贷3%、公积金贷2.6%、15年 | 两种利率预设，单笔等额本息，期限15年可改 | 符合预设；没有组合贷，也不计算贷款资格 |
| 现金首付与公积金分开 | 单独现金首付，余额8万元、月缴存2000元；留存、月抵扣、一次性投入 | 符合；资格由用户确认 |
| 满二满五及可变现价值 | 默认5年假设出售；按月跨23/24/59/60边界，扣债务、税费、出售费用；继续持有另列非现金房屋权益 | 符合估算需求；没有交易流动性或实际售出时间模型 |
| 为什么得到这个结果 | 9项账目贡献可对账，4参数逐项扫描，固定规则研究手记 | 符合；扫描排名依赖设定的变动范围，不是通用因果重要性 |
| 滑块、清晰、美观 | 数字与滑块双入口，桌面两栏，移动端不溢出，错误输入阻止旧结论显示 | 基本符合；移动端输入与结果相距较远 |
| 原创动漫助手和3种图案/动作 | 实际为同一个人的半身、Q版两张。都偏讲解动作；只有整体轻浮动，无思考/提醒状态切图 | 部分完成；应明确承认差距 |
| GitHub/Vercel及Hub兼容 | 静态构建、相对路径、本地计算、不绑定后端 | 工程条件具备；尚未实际部署/集成验证 |

## 角色建议

不用因为“想过三张”就补第三张同姿态。现有半身负责品牌、Q版负责结果入口，职责合理。下一步真正值得增加的是同身份“思考/提醒”姿态，在参数缺失或需要核实假设时使用；可与当前讲解姿态形成有意义的区别。不要按买/租胜负做“开心/失望”表情，以免暗示偏向。当前版本可先演示，视频中不声称角色会对话或已有三种状态。

## 新手体验优先级

1. 移动端增加轻量“查看结果/回到参数”定位入口，先解决改数后找结果的问题。
2. 增加一行逐步展开的比较公式，并用白话先讲“钱从哪里来、花到哪里去”；现有账目和模型说明尚未完整实现早期“公式进化”的学习过程。
3. 角色随当前操作给一句具体提示（而非固定鼓励语），之后再补第三姿态。现有研究手记会随数值重算，但气泡不会逐次解释滑块变化。
4. 首次公开发布前优化角色素材体积、测试实际Vercel路径。当前两张PNG合计约4MB，移动网络首屏不如本机快。

以上是审核建议，本次不将新体验设计冒充已交付功能，也未改动计算口径或角色图。

## 计算可信度与边界

默认300万元、月租4500元、五年、全款、房价不变、现金年化1.5%、出售费1%、买入和持有额外费用未填，买房净资产约多18278元；不是默认把自住出租收益算了两遍。主要是住房开销差270000元、现金收益差约负221722元、出售费用负30000元。仅将住房月租改为3000元即可改变结论。未填写购入费用会偏向买房，视频需露出默认前提，实际决策必须补齐自己的费用。

两方案按相同起始现金、公积金和每月外部预算比较；本金与公积金提取不计为利润；期末出售不重复扣债务。公积金属于受限资产，总净资产不等于可立即花的钱。期末房价是假设；中途按购入价记账的曲线不是市场走势预测。

政策复核：2026年个人出售购买不足2年的住房按3%征收率估算增值税，含税价换算为价/(1+3%)*3%；满2年免增值税。满5年仍须满足家庭唯一等条件才能按对应规则免个税。模型仅覆盖有原值凭证的普通购入住房差额计税情景，其他地区、取得方式、核定征税等可手动覆盖总税额。默认12%附加综合比例属于保守试算假设，不代表所有人实际适用。

- [上海2026住房交易税费梳理](https://www.shanghai.gov.cn/nw17239/20260423/db84274a588149309032977a3df7f916.html)
